## 4. Analyse détaillée par service

### 4.1 Networking — €16.79 net (€20.75 usage, +5 %)

**Décomposition SKU** (confirmée par Gemini Cloud Assist) : **€16.28 sur *Cloud Load Balancer Forwarding Rule Minimum Global***, soit **97 % du poste**. Le reste (~€4.47 brut, ramené à ~€0.5 net par le free tier) = egress + Cloud CDN de la landing.

**Ce qui tourne** : 2 forwarding rules (`cc-https-rule` + `cc-http-redirect-rule`) sur l'IP `34.36.87.103`, **3 certificats managés** (api / app / apex+www — le 3e ajouté le 01/07 avec la landing), 1 backend bucket CDN (`cc-backend-landing`).

**Verdict** : **plancher incompressible et conforme**. Le LB Global HTTPS est facturé à l'heure (~€17/mois) que le trafic soit de 1 ou 100 000 requêtes. C'est le prix des noms de domaine `app.` / `api.` / `com-compass.com`. La landing ajoutée en juillet n'a **rien** coûté de plus en structure (elle réutilise le LB existant) — elle explique juste le +€1.3 d'egress/CDN.

### 4.2 Compute Engine — €13.97 net (−4 %) 🔴 **LE gisement restant**

**Ce qui tourne** : **rien d'applicatif**.

```
$ gcloud compute instances list --project=cacaooo   →  Listed 0 items.
$ gcloud compute disks list     --project=cacaooo   →  (vide)
$ gcloud compute networks vpc-access connectors list
```

**Preuve par élimination** : depuis le 03/08 le bastion est **éphémère** (créé/détruit par `.local/db-prod.sh`), et sur août 1→9 le projet ne contient **aucune VM ni aucun disque**. Compute Engine facture pourtant **€3.97 sur 9 jours = €13.7/mois**. Il ne reste qu'une seule ressource Compute facturable : les **2 instances e2-micro du `cc-vpc-connector`, allumées 24/7**.

L'hypothèse formulée en juin (§4.3 du rapport précédent) est donc **confirmée, plus une supposition**. Et le montant est plus élevé qu'estimé : **€13.7/mois, pas €10-12**.

**Ce que c'est fonctionnellement** : le tunnel réseau privé qui permet au backend et aux 24 jobs d'atteindre Cloud SQL, qui n'a pas d'IP publique. C'est indispensable — mais la technologie utilisée (Serverless VPC Access Connector) est l'ancienne génération, facturée à la machine allumée. **Direct VPC Egress** (GA sur Cloud Run) rend le même service en facturant au trafic. Voir §5.2.

### 5.2 P0 — Direct VPC Egress (la seule action à fort ROI restante)

**Le constat** : €13.97/mois pour 2 machines e2-micro qui ne font que router du trafic vers Cloud SQL, allumées 24/7 même la nuit et le week-end où rien ne tourne. C'est **27 % de la facture** pour un composant que Google a rendu obsolète.

**Direct VPC Egress** (GA sur Cloud Run) supprime l'infra fixe : Cloud Run se branche directement sur le subnet, facturation au trafic uniquement.

**Procédure** :
1. Créer un subnet dédié pour Direct VPC Egress.
2. Migrer les 2 services + **24 jobs** : remplacer `--vpc-connector` par `--network` + `--subnet` + `--vpc-egress=private-ranges-only` (dans `deploy.yml` et Terraform).
3. Valider la connectivité Cloud SQL **job par job** sur un cycle de pipeline complet.
4. Supprimer `cc-vpc-connector` une fois le cycle validé.

**Risque réel** : ce n'est pas un simple flag. **26 workloads** dépendent de ce chemin réseau pour joindre la base. Un raté = pipeline nocturne KO. À faire un vendredi soir hors fenêtre de pipeline, avec rollback prêt (le connector se recrée en ~5 min).

**Économie** : **−€13/mois soit −€156/an**, pour ~0.5 jour d'effort. ROI immédiat.
