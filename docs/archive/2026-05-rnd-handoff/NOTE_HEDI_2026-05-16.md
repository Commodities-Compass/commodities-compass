## 2. Récupérer les scraps Com Compass quotidiennement → alimenter Optimizer

### Le besoin

Com Compass scrape des données externes (cours, news, etc. — je ne connais pas le périmètre exact). Je voudrais que **chaque jour ouvré, les résultats des scraps qui peuvent enrichir le dataset Optimizer soient automatiquement intégrés**.

Cas d'usage concret : si Com Compass commence à scraper la météo Ghana en temps réel (au lieu d'ERA5 mensuel décalé), ça pourrait rentrer en feature `era5_t2m_realtime` ou similaire et **booster la prédiction court-terme** (le cœur du projet — cf `CLAUDE.md` postulat 100 jours).

### Ce dont j'ai besoin de toi

1. **Inventaire des scraps Com Compass actuels** : quelles sources, quelle fréquence, quel format de sortie (CSV, parquet, DB ?) → liste avec le nom de chaque champ.

2. **Identifier ceux qui ont un délai < 1 jour** par rapport à la session de trading → ceux-là sont les vrais candidats pour enrichir le dataset Optimizer.

3. **Pipeline d'export quotidien** : comment Com Compass peut pousser ces données vers un endroit où l'Optimizer V3 peut les consommer ? Options :
   - **Option A (simple)** : Com Compass écrit un CSV/parquet quotidien dans un dossier partagé (`data/external_scraps/YYYY-MM-DD.csv`). L'Optimizer le merge dans le dataset au démarrage.
   - **Option B (propre)** : une route API côté Com Compass (`GET /api/scraps/latest`) que l'Optimizer interroge avant chaque run.
   - **Option C (lourd)** : DB partagée (Postgres/BigQuery). Plus complexe, surdimensionné pour un volume horaire.
   
   **Recommandation pragmatique** : Option A pour démarrer, B plus tard si volume.

4. **Schema agreement** : pour qu'un scrap puisse rentrer en feature Optimizer, il faut respecter le contrat :
   - 1 ligne par jour ouvré
   - Colonne `date` obligatoire (format ISO `YYYY-MM-DD`)
   - Pas de look-ahead bias (la valeur du jour J doit être connue à J0 + features d'horizon antérieur seulement)
   - Si donnée hebdomadaire → carry-forward jusqu'au prochain release

### Ce que je code de mon côté

- Module `optimizer_v3/external_features.py` qui charge le ou les fichiers `data/external_scraps/*.csv` pondus par Com Compass, merge sur la colonne `date`, propage en forward-fill si données hebdomadaires.
- Ajout de chaque feature scrapée dans le registre `criteria.py` (statut `non-testé` au démarrage, Phase 1 Stability Selection décide si elle survit).
- Documentation des nouvelles features dans `CLAUDE.md`.

→ **Côté Hedi : inventaire scraps + délai par source + recommandation Option A vs B.**
