## 4. Analyse détaillée par service GCP

### 4.1 Compute Engine — €18.37 (+123 %)

**Ce qui tourne** :
- 1 VM unique : `cc-bastion` — e2-micro déclarée, 10 GB pd-standard, sans IP publique.
- Rôle : tunnel IAP pour accéder à Cloud SQL en réseau privé (`gcloud compute ssh cc-bastion --tunnel-through-iap`).

**Anomalie de coût** :
- Une e2-micro 24/7 en europe-west9 + disque 10 GB devrait coûter **~€6/mois**.
- On observe **€18.37**, soit ~3× la borne théorique.
- Hypothèses à valider :
  1. La VM a été redimensionnée au-delà de e2-micro à un moment (à vérifier via `gcloud compute instances describe`).
  2. Snapshots automatiques de boot disk accumulés (sans politique de purge).
  3. Boot disk plus gros que 10 GB en réalité.
  4. Sustained-use discount mal appliqué.

**Pourquoi +123 % vs mars** : mars n'avait probablement que ~15 jours d'uptime (création récente). Avril = premier mois plein.

**À vérifier** :
```bash
gcloud compute instances describe cc-bastion \
  --zone=europe-west9-a --project=cacaooo \
  --format='value(machineType,disks[].diskSizeGb,disks[].source)'
gcloud compute snapshots list --project=cacaooo \
  --filter='sourceDisk~cc-bastion'
gcloud compute disks list --project=cacaooo \
  --filter='zone:europe-west9-a' --format='table(name,sizeGb,type,users)'
```

### 4.2 Networking — €17.75 (+643 %)

**Ce qui tourne** :
- **Global HTTPS Load Balancer** : 1 forwarding rule + 2 SSL certs Google-managed + IP statique (`cc-lb-ip`). Routes : `app.com-compass.com → frontend`, `api.com-compass.com → backend`.
- **Serverless VPC Connector** `cc-vpc-connector` (min=3 instances, throughput 200-300 Mbps) — utilisé par le backend et tous les Cloud Run Jobs pour atteindre Cloud SQL en privé.
- **Egress** : minime à ce volume de trafic.

**Décomposition estimée** :
- LB forwarding rule : **~€17/mois** (plancher fixe du LB Global HTTPS, ~$0.025/h × 720h).
- VPC connector throughput : ~€0-5/mois selon trafic (les e2-micros idle du connector sont possiblement facturées en Compute, pas ici).
- Egress LB : <€1/mois.

**Pourquoi +643 % vs mars** : le LB custom domain a été activé fin mars / début avril → premier mois plein de facturation.

**À vérifier** :
```bash
gcloud compute forwarding-rules list --project=cacaooo --global
gcloud compute backend-services list --project=cacaooo --global
```

### 4.4 Artifact Registry — €7.81 (+2419 %)

**Ce qui tourne** :
- 1 repo Docker `commodities-compass` en europe-west9 contenant 3 images :
  - `backend` ~200 MB
  - `frontend` ~50 MB
  - `jobs` ~1 GB (Playwright + Chromium pré-installés)

**Politique de rétention actuelle** (terraform) :
- KEEP last **10** tagged versions
- DELETE untagged > **7 jours**

**Calcul théorique** :
| Image    | Taille | × 10 tags | Coût @ €0.10/GB/mois |
|----------|-------:|----------:|---------------------:|
| jobs     |   1 GB |     10 GB |               €1.00  |
| backend  | 0.2 GB |    2.0 GB |               €0.20  |
| frontend | 0.05 GB|    0.5 GB |               €0.05  |
| **Total tagged** |     | **12.5 GB** |          **€1.25** |
| Untagged en attente |  | ~5-15 GB | ~€0.50-1.50         |

**Total estimé : €1.75-2.75/mois** — on est à **€7.81**, soit 3-4× la borne haute. Possibilités :
- La politique « KEEP last 10 » s'applique par tag, pas par image — l'addition réelle peut dépasser 30 GB.
- Push/pull operations facturés (chaque déploiement push 3 images, et Cloud Run pull à chaque cold start).
- Bandwidth de pull facturé (chaque exécution de Cloud Run Job pull 1 GB de Playwright).

**Pourquoi +2419 % vs mars** : premier mois avec un volume de déploiements normal (chaque push to main = 3 images poussées). Mars n'avait que quelques builds.

### 5.2 P0 — Stopper le bastion quand non utilisé

Le bastion ne sert qu'à l'accès DB manuel via tunnel IAP. Aucune raison de le laisser tourner 24/7.

**Option A — manuel** (immédiat) :
```bash
# À la fin de chaque session DBA :
gcloud compute instances stop cc-bastion --zone=europe-west9-a --project=cacaooo

# Restart à la prochaine session :
gcloud compute instances start cc-bastion --zone=europe-west9-a --project=cacaooo
```

**Option B — auto-stop nocturne** (recommandé) : ajouter un Cloud Scheduler qui stoppe le bastion chaque soir 22:00 UTC. Si tu en as besoin, tu le rallumes en 30s.

**Option C — supprimer complètement** : utiliser un Cloud Run Job ad-hoc avec `cloud-sql-proxy` pour les requêtes manuelles (plus complexe, mais €0/mois).

**Économie attendue** : passer de 720 h/mois à 10-20 h/mois → **~€16/mois**.

---

### 5.3 P0 — Réduire la rétention Artifact Registry

Modifier `infra/terraform/artifact_registry.tf` :

```diff
- # KEEP last 10 tagged versions
+ # KEEP last 3 tagged versions
- # DELETE untagged > 7 days
+ # DELETE untagged > 1 day
```

Tu peux toujours rollback sur les 3 derniers tags. Si besoin de plus, recréer une image. **Économie attendue : ~€5/mois**.

---

### 5.4 P1 — Migrer vers Direct VPC Egress

Le `cc-vpc-connector` actuel maintient 3 instances e2-micro idle en permanence. **Direct VPC Egress** (GA depuis 2024 sur Cloud Run) supprime cette infra fixe : pas de connector à provisionner, billing au prorata du trafic seulement.

**Procédure** :
1. Créer un subnet dédié pour Direct VPC Egress.
2. Modifier les Cloud Run services + jobs : remplacer `--vpc-connector` par `--network`+`--subnet` avec `--vpc-egress=private-ranges-only`.
3. Tester en staging que la connectivité Cloud SQL fonctionne toujours.
4. Supprimer le `cc-vpc-connector` une fois la migration validée.

**Économie attendue** : €5-8/mois (selon où exactement les coûts du connector sont facturés).

### 5.6 NON — Couper le LB

Économiser €17/mois en exposant `*.run.app` à la place de `app.com-compass.com` ferait perdre le custom domain (impact UX, SEO, branding, futur SSO B2B). **Pas recommandé** sauf en mode pré-revenue extrême — €17/mois pour une marque c'est négligeable. À reconsidérer uniquement si la trésorerie devient critique.
